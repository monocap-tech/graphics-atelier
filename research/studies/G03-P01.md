# G03-P01 — One model, three raster treatments

Status: proposed R2 recipe (not executed; target footage and software versions not yet registered). G01/G03 overlap; this is a small comparative lab, not a mandatory aesthetic specification.

## Target

An original articulated mechanical drone, readable at gameplay scale while turning through a full rotation. Observable requirements: recognizable core and one asymmetric feature, stable registration, coherent shade direction, no unwanted fringe or color count inflation. C-Dogs SDL before/after animation in SRC021 is an operational precedent; SNK SRC001 is an assisted-drawing comparator; APO+ SRC013 is a reference-redraw comparator, not a drone recipe. Before a fidelity claim, register an exact lawful commercial reference frame/segment and inspect it; target here is provisional technical behavior only.

## Proposed constraints

64x64 transparent cell; fixed center pivot (32,32 edge-coordinate convention); 8 frames at 45 degree increments; 12 fps preview; 16 opaque RGB colors maximum plus binary transparency; fixed orthographic camera, fixed yaw-independent light in world coordinates; no per-frame cropping. These are proposed lab constraints, not original hardware facts. Use installed Blender and Aseprite; record exact versions. ImageMagick optional, use existing export features first. No paid add-ons needed. Time-box to 2–3 hours of operator time for initial specimen; record actual time and stop at blocker rather than relax a gate silently.

## Recipe

1. Sketch a distinctive mechanical silhouette; model body, two articulated pods and asymmetric antenna with primitives. Place origin at model center. Preserve .blend and sketch.
2. Orthographic camera fixed with framing margin; set 64x64 output, transparent film, fixed exposure and color management. Light with a single directional/area source and controlled ambient. Select engine available in installed version. Render 8 PNGs by rotating the drone around the world vertical axis in 45 degree increments; center camera and maintain scale. Inspect raw alpha and color counts.
3. A: automated processing — convert transparent edges to binary alpha using declared threshold 128; map opaque RGB to a single 16-color palette (no dithering for baseline); preserve transparent pixels separately. Import ordered sequence into Aseprite and export 8x1 sheet and JSON; no per-frame hand editing.
4. B: duplicate A into a new Aseprite source file. Correct silhouette, narrow features, highlight placement and inconsistent clusters manually. Preserve common palette and exact canvas/pivot. Log changed pixels and time; no 3D changes between A/B.
5. C: use raw frames as drawing references, hand-redraw frames in a separate source file with same palette/cell contract. Optional full C if time budget permits; otherwise one frame and label partial/non-comparable for motion.
6. Preview native size, nearest-neighbor 4x enlargement, then against light and dark backgrounds. Compare in randomized order if possible, no claim of formal perceptual validation.
7. Transfer to a materially different second drone (different silhouette and articulation); rerun selected workflow once. Do not claim R4 until second complete sequence.

## Acceptance checklist

- 8 correctly ordered 64x64 frames, 512x64 packed sheet; fixed registration, no clipping; alpha values only 0/255; <=16 distinct RGB triples among opaque pixels across all frames.
- Inspect silhouettes and rotational motion; flag disappearing antenna/pods, noisy outline, shading discontinuity, or apparent jitter due to inconsistent pivot. Animation should communicate rotation; numeric pivot test and visual review are separate.
- Compare manual effort, correction count, source editability, ability to rerender and maintain common palette. Prefer simplest acceptable method for repeated mechanical assets.
- Preserve source files, raw frames, processed frames, sheet/JSON, contact sheets, timings, palette, exact app versions and rerun instructions. No ripped reference assets in repo. If a software prerequisite is missing, record as blocked.

No measured results yet. The benchmark is a provisional design experiment, not a claim of equivalence to Gunvolt or SNK.
