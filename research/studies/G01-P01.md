## A. Semantic control

Run `node labs/G01-P01/indexed_control.mjs` (Node executable not needed for the original sandbox run; same pure function evaluated there). ## B. Aseprite operator exercise

1. Record version (Help/About or command version), create 32x32 transparent indexed document; choose a 16x16 grid for registration, not forced asset dimensions. Reserve index 0 for transparent in this lab. Set 5 palette entries (1 transparent, 4 opaque) with deliberate visual roles. Keep base dark/base/light ordered, accent separate. Save source as `drone.aseprite`. Use your own design, not copied sprites.
2. Draw one original mechanical object with a stable origin. Inspect 1:1 preview and a high zoom. Create two distinct emitter/pose frames, with tag `idle`, 100 ms each. Maintain fixed canvas and named layers body/emitter; record intended origin in notes. Add a named slice for the cell if useful; verify exported coordinate mapping rather than assuming metadata format.
3. Save two equal-length palette files (e.g. `bank-a.png`, `bank-b.png`; verify actual palette indices and zero transparency). Duplicate the document before destructive edits. Change one palette entry and inspect all pixels of that index. Reorder palette entries with and without an appearance-preserving remap; compare actual decoded RGBA and index assignment. Keep the transparent role fixed.
4. Make the following command-driven export after creating `export/` and verifying the Aseprite executable is on PATH. CLI options sourced from official documentation; actual paths, format, tag/slice flags and version must be verified; `--list-tags` and `--list-slices` precede the input.

```sh
aseprite -b --list-tags --list-slices drone.aseprite --sheet-type horizontal --sheet export/drone.png --data export/drone.json
aseprite -b drone.aseprite --palette bank-a.png --sheet-type horizontal --sheet export/drone-a.png --data export/drone-a.json
aseprite -b drone.aseprite --palette bank-b.png --sheet-type horizontal --sheet export/drone-b.png --data export/drone-b.json
```

5. Inspect decoded dimensions, alpha, palette entries, frame order/duration, registration; expected untrimmed two-cell sheet 64x32 if export keeps full canvas. Record any automatic flattening, trimming, palette conversion or opacity problem. Rerun without edits and compare decoded pixels and normalized metadata; binary file identity not mandatory.
6. Change one visual detail, regenerate and verify both variants update correctly without editing exported PNGs. Compare with hand-recoloring duplicated drawings; measure revisions/time. Add a second distinct object before claiming generalized workflow.

## Acceptance

For the controlled bank test, index geometry and alpha remain stable under recolor; appearance preserved under correct remap; wrong remap visibly alters output. For actual editor exports, verify all gates independently. Reject or document a changed alpha, palette role, registration, ordering, duration or unintended color inflation. Add no custom editor until a demonstrated friction point. Separate engine palette lookup as a later runtime architecture experiment, not necessary for offline variants.
