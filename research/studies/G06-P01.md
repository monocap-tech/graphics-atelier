# G06-P01 — Semantic effect family and compositing control

2026-11-18. Scalar analytic control executed; actual editor/runtime production proposed.

## Executed control

Normalized scalar linear-light values, opaque destination, no tone mapping or color conversion. Normal blend N(b)=a*c+(1-a)*b, additive A(b)=b+e. Example a=0.25, c=0.4, e=0.35, backgrounds [0,0.2,0.4,0.6]; no clipping occurs. Combined result 0.45+0.75b. A normalized single straight-alpha layer reproducing slope must use opacity 0.25; matching intercept then requires color 1.8, impossible within [0,1]. An ordinary layer with color 1 supplies at most 0.25+0.75b. A separate normal and additive pass reproduces this simple composition algebraically. HDR or other blend semantics are outside that impossibility claim; arbitrary interleaving, nonlinear processing, distortion and export quantization not proven representable.

Second fixture: opaque bullet intensity 0.86, neighbor background levels 0.12/0.50/0.75, additive glow 0/0.35/0.75 over both samples before or after bullet insertion, clamp to [0,1]. Measure signed center-minus-neighbor difference. A foreground additive field may saturate both to 1 and erase contrast; background-only glow may also make neighbor as bright or brighter than bullet. A deliberately imposed local background/FX ceiling of 0.35 preserves >=0.51 in this fixture by construction. This is an illustrative intervention, not a recommended universal cap, perceptual metric, actual shader or proof of legibility; it may destroy desirable art and can require background adjustment rather than suppressing effects. Outlines, hue, temporal separation, control and spatial variation not measured.

Run `node labs/G06-P01/effects_control.mjs`; same pure JS function executed in sandbox, Node CLI not separately exercised. Six sanity checks passed. See [results](../../labs/G06-P01/results.json).

## Operator study (not executed)

Target: one original mechanical attack with a readable short charge, active beam, release, and hit/cancel response, plus a decorative wake. Commercial target footage and timestamps still to register. Use Effekseer and/or Unity Particle System where installed, Aseprite for original masks/textures and Blender for optional geometry. Record tool versions and package/render pipeline compatibility. Start with static background proxies then G04-G05 scene if available.

1. Specify logic-owned attack state and event timestamps (local test: 60 Hz; charge 30 ticks, beam active 18 ticks, recovery 24 ticks). Cancel during charge, end while firing, and restart cases. Beam geometry/active bounds and movement are authoritative simulation values, independent of random particles. These times and attack types are proposed experimental fixtures only.
2. Draw masks: soft radial glow, sharp core, narrow streak, segmented ring, optional smoke. Separate persistent core, directional motion and ephemeral particles. In Effekseer assemble charge ring, emission/exhalation and burst nodes; ribbon/track according to orientation need; attach explicit origin/muzzle from G03. Use exported project and named resources, stable preview settings and duration. Dynamic input or triggers only if supported by installed version; otherwise explicit start/stop/play instances and document restrictions.
3. Compare three treatments of equal underlying trajectory: A minimal bright core/clear charge marker; B decorative effects over gameplay; C large effects behind and limited front accents, separate core and contrast protection where justified. Test sparse and dense bullet fields, dark/bright patterned backgrounds, moving camera, visibility under reduced motion/flash. Record visual failures; do not make danger depend solely on color or a glow.
4. Compare live effect to fixed baked sequence with identical timing; use normal and additive exports as separate passes when relevant, compare against actual engine captures on at least two backgrounds. Distortion requires scene sampling and cannot generally be conveyed by background-independent transparent frames. Record actual renderer setup, blend modes/alpha convention, linear/gamma/HDR, depth/order, logical vs output grid, sampling, viewport. Disable distortion first as baseline.
5. Test 30/60 render fps or other available rates with simulation tick fixed, time-scale/pause, cancellation, restart and seeded variants when feasible. Check no effect restarts or lingers as misleading active state; residual nonhazard indication must be distinguishable. Verify the same input yields identical underlying attack and bullet sequence for all visual treatments.
6. Preserve result sources, original textures, sample capture frames, comparison clips, export settings, event trace, version/license metadata and operator times. Profile frame time/overdraw only in actual runtime; compare costs with baseline. No external project or proprietary media in public repo unless separately cleared.

Gate: state and core onset/offset correctness against recorded trace, no missing attachments or stale misleading effects, documented visual priorities and reproduction on chosen backgrounds, one engine export revision propagated. Subjective legibility needs appropriate comparison or viewer test; scalar proxy alone insufficient. Repeat distinct effect family (e.g. projectile impact) before R4. Suggested first operator session capped at 3h, selected as a local study budget, not a duration estimate or demand to complete all modes.
