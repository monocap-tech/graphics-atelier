## 1. Format and sample

ACBF 1.1 XSD: page references an image and optionally contains text layers, frames and jumps; page transition attribute optional. frameType requires a points string, jumpType requires points and page; text-area can have separate type, color and rotation etc. The format narrative describes pixel-coordinate point lists and navigation order. Structural XSD validation is not numerical polygon validation. Sample Craphound 1.1 XML contains English and Slovak text overlays and polygon frames, image references and stated CC BY-NC-SA 3.0 US license. No images or dialogue copied. Count of frame elements from retrieved XML using regex restricted to frame start tags with points: 151; 116 four-vertex, 35 more than four vertices, maximum 90. Four vertices do not imply axis alignment. Counts are sample-specific, not a population estimate. Code Mode arithmetic performed on retrieved point lists, not viewer execution or schema validation.

Fourth serialized frame: bounds x=545..995, y=452..1017; rectangle 450×565 = 254250 px²; polygon shoelace absolute area 237662.5 px², excess rectangle area 16587.5 px² (6.5241% of rectangle), assuming simple polygon and continuous coordinates. No raster pixel count; no source image viewed and no claim about what neighboring content is actually revealed. This is a reproducible metadata comparison, not a visual inspection. Distinguish the selected frame's polygon from a destination viewport and optional runtime mask.

## 2. Authoring/export — Krita

Pinned Krita code: comics_exporter.py creates page transform (lines 349–355): crop offsets cropx/cropy, document resolution/72, width/height scales of resized projection relative to original. Shape extraction (426–597) uses bounds plus limited SVG shape parsing and manual transform handling; curves/rotations/unsupported shapes may be approximate. README (178–180) describes search for text/panel layers; writer CPMT_ACBF_XML_Exporter.py (435–487) loads output image, uses stored coordinates to multiply by resolution ratio, subtract crop offsets, multiply by separate resize scale, truncate and clamp each coordinate; appends non-text geometry to frameList and text geometry to text-layer. Writes frames to page or cover (588–597). Translation overlays separately generated. Candidate notation q=clamp(trunc(A(rp-c))), where p is document shape point, r=resolution/72, c=crop offset in image pixels, A=diag(scaleWidth,scaleHeight). Image rect is adjusted by code; exact edge semantics and rotated transforms require a fixture, not inferred conformance. Vertex-wise clamping is not general geometric polygon clipping; note for future crop stress tests. No claim of an executed export or direct Krita-to-sample provenance.

## 3. Reader — ragtag/panel-by-panel

Pinned JS: parseACBF / parsePage (551–604) parses XML to an object, page images and points lists, then pointsToPercent (357–383) normalizes by image natural dimensions and reduces each point list to axis-aligned extrema and center. focus (413–455) chooses full page when currentPanel=-1, otherwise chosen rectangle; aspect-based scale equals min(viewportW/boxW,viewportH/boxH) in natural-image units. Anime.js animates page element scale and percent translation toward panel center with configured 750 ms easeOutExpo. Whole-image transform rather than a polygon-mask operation in the inspected path; viewport may show surrounding material. No claim about final CSS transform origin or every layout; browser not run. next/prev (645–679) advance/reverse index, transition between page and panel; full page is a distinct state. Input handlers (180–212) next/previous via keyboard and swipe. Resize refocus (30). README limits support to external-referenced ACBF subset and explicitly excludes text areas. No transition/hotspot/translation playback claimed. 750 ms is transition duration, not narrative duration.

Possible static edge-case defects: xmlToJson (625–638) stores a single same-name element as object until a duplicate promotes it to array, whereas parsePage loops page.frame.length and parseACBF loops body.page.length. A one-frame or one-page document may therefore be skipped. prev indexes the previous page before checking negative page index; navigation from first page may throw. These are untested static findings, not verified browser failures. Do not fix upstream or use as production recommendation.

The sample XML and reader support are distinct: sample references external images; we inspected only metadata and do not claim the bundled sample plays in this reader, especially text overlays. Metadata preservation and actual playback fidelity are separate quality gates.

## 4. Independent standard comparator

IDPF EPUB Region-Based Navigation 1.0 (2015), sections 3.4–3.5 and appendix A: ordered navigation lists link to fixed-layout documents and regions; nested subregions permit attention within a panel, alternative paths, and optional synthetic regions spanning adjacent pages. Rectangular fragments support percent or pixel coordinates; circle/polygon and SVG regional mechanisms have separate support requirements. Siblings can be merged by a supporting reader; hierarchy constrains merging. To intentionally show a whole panel after details, author may include a child with the parent's geometry. Spec describes possible reader behavior, not verified reading-system implementation or authorial equivalence. No assumption feature widely supported by current readers. Region metadata is navigation affordance, not necessarily visual mask. This is useful for Furudate's spread/page reading alternatives and PN04 editorial co-visibility issues.

## 5. Candidate contract and stop condition

Keep editable source points and transforms; exported outline polygon; viewing bounds; clip/mask (if intended); destination viewport; ordering graph/hierarchy; text/semantic anchors; full composition/co-visibility and reveal/input transitions as independent fields. A bounding rectangle fitting the viewport is a valid presentation choice only when intended and qualified. Preserve layer/source identity and named safe cues; explicitly log approximation, rounding, crop, clipping and unsupported features. Validate source geometry against export after a crop/rescale; then test full-page, polygon focus, neighboring content, overlapping/embedded and two-page groups in a real renderer only if selecting a production target. No universal format, authoring application, license or runtime selected. No independent complete historical shōjo example resolved.
